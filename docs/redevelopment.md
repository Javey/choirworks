### 相比错误基线的关键修正

- 会话状态以 `contexts` 为真源；计划跨消息与重启存活，不再宣称仅由 Task.metadata 保存完整状态。
- 编排器需要理解交活意图（交付 / 求助 / 调整计划），但不评判质量、不润色汇总。
- 直接依赖的产出原文交给下游，带不可信内容围栏和截断标识；不传间接依赖。
- 失败修复是增量计划补丁，保留已交付节点；进行中节点未经人类确认不得自动作废。
- 隐藏式回合回退是当前明确需求，不能列为待定的旧功能；不等同于旧检查点回滚。
- 人工介入是独立通道，可并发、须定向答复、可取消；等待不自动超时。同伴协助不走该通道：编排层为无实体的规划层，选定同伴后派生 helper 节点，其结果回填为 `node.answer_from` 并让原节点续跑，不产生任何人类问答卡。
- 事件沿用新基线的 function call、状态增量（`cw_delta`）、UUID artifact 与统一 replay 路径；status 事件不带 `kind` 判别字段，语义由载荷结构（`cw_delta`/`intervention_id`）承载。

## F02 接口契约

| 操作 | 成功 | 失败 |
|---|---|---|
| POST /v1/agents | 201，含卡片能力、health、last_seen、created_at | 非法字段 422；重名（含并发）409；远端发现失败/卡片不可用 400 |
| GET /v1/agents | 200，按名称排序 | 数据库错误按服务故障处理，不伪装为卡片错误 |
| POST /v1/agents/{id}/refresh | 200，更新能力与 last_seen，保持 ID 和 created_at | 不存在或刷新中已删除 404；远端失败 502，health=unavailable，保留旧卡片和最后成功时间 |
| DELETE /v1/agents/{id} | 204，无响应体 | 不存在 404 |

- 名称去首尾空白；1–64 位，以英文字母/数字开头，仅含英文字母、数字、下划线、连字符，与当前 @ 命名形式一致。
- card_url 是 HTTP(S) **基础地址**，不是完整的 agent-card.json 地址；去尾部斜杠，不接受凭据、查询串和 fragment。
- 当前南向客户端使用 JSONRPC，接受的卡片必须包含 JSONRPC / A2A 1.0 接口和有效 HTTP(S) 地址；不是所有 A2A 绑定都已支持。
- health 表示最近一次注册/主动刷新结果，不是周期性心跳。注册失败不新增记录；刷新恢复后重置为 ok。
- 注册/刷新后的新调用使用缓存的新卡片；失效旧客户端不立刻关闭共享 HTTP 池，避免打断已有请求；退出时统一清理。
- 删除注册项不代表取消它已经接收的任务。任务取消由单独流程负责。
- 数据持久化验收针对普通应用启动；模拟模式的清库和远端端口恢复留在 F18，不在本项混入修改。
