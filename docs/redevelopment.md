## 2. 冲突与建议决策

| 议题 | 文档冲突 | 建议本轮口径 |
|---|---|---|
| 状态存储 | 旧版独立事件日志/投影；新版 SDK TaskStore | A2A Task 为执行聚合根，metadata 保存编排状态 |
| 群与任务 | 旧版合成长期 Room Task；新版 Context 包含多个 Task | 群 ID 为 contextId，任务 ID 为 taskId；终态后新建同群任务 |
| 求助策略 | 旧版 auto_llm → peer → human；新版 LLM 在 peer/human 二选一 | 统一求助决策，LLM 不可用转人工；不让编排器代专家作答 |
| 完成总结 | 旧群聊设计要求汇总；产品文档明确禁止 | 专家产出为最终交付，编排器只播报调度状态 |
| 运行中输入 | 旧前端禁用；群聊/产品文档要求非阻塞 | 输入保持可用，明确反馈排队、独立任务或打断结果 |
| 断线恢复 | 旧 SSE seq 回放；A2A 快照加 live | 用户可见结果不重不漏；以持久快照补齐并恢复订阅，不承诺重放每一历史分片 |
| 检查点/回滚 | 早期核心需求，新版无实现且未明确用户是否仍需要 | H01–H02 待确认范围；如保留，需要在 SDK 架构上重新设计 |
| 手动重试、澄清与审批 | 历史需求，新版只覆盖部分 | H03–H05 待确认；不使用旧接口占位假装可用 |
| 部署入口 | 旧前端文档要求静态托管；当前代码已经移除 | 先用前后端分离完成开发验收；生产托管方式单独确认 |

## 3. 功能点与验收顺序

每一行是一次独立交付。实现和测试允许复用现有可用模块，但必须按验收标准重新确认，不能凭旧状态表跳过。当前除 F01 外全部未开始。

| 编号 | 功能点 | 验收标准 | 当前差距/依赖 |
|---|---|---|---|
| F01 | 离线演示的确定性规划与验收样例 | 无模型 Key；技术开发、代码评审、财务、审批、协作、重试、降级各自选对 Agent；真实 prompt 下仍正确；示例说明与实际一致 | 模拟请求解析混入能力描述；财务/审批路由与示例不符；本轮第一项 |
| F02 | Agent 注册、发现与维护 | 注册/列表/刷新/删除；缓存能力和健康状态；重名、不可达、非法输入可理解地报错 | 后端已具备基础实现，需要验证边界；不新增文档列为非目标的管理页 |
| F03 | 标准 A2A 任务生命周期 | 官方 SDK 可发现、发送、查询、订阅、取消；校验参数/版本；终态不可继续写入原任务 | 作为前端和编排的协议基础，固定真实协议夹具 |
| F04 | 会话创建、列表、持久化与多轮历史 | 首条消息创建群；同 context 的多任务只列一个群；标题/时间/排序正确；刷新后历史完整；追问仍属原群 | 当前列表按 task 展示，创建接口未持久化；依赖 F03 |
| F05 | 基础群聊界面与消息展示 | 人类、assistant、Agent、系统四类展示；原始请求正确回显；产物形成消息；错误/加载/空态；刷新不丢历史 | 当前主区为 DebugEventList；依赖 F04 |
| F06 | LLM 规划与计划展示 | 真实/模拟 LLM 共用 schema；Agent/skill 有效、节点唯一、无环、数量受限；非法计划反馈重试；规划理由与任务分工可见 | 现有 Planner 可复用；模型失败需完整错误收敛；依赖 F02/F05 |
| F07 | DAG 串并行执行与依赖输出传递 | 独立节点按并发上限执行；下游等待上游且收到其产出；某节点等待不阻塞其余工作；执行状态可见 | 当前调度存在但下游只收到 input_text；依赖 F06 |
| F08 | 流式产物、任务面板与断线续订 | 增量文本/多产物正确合并；计划与节点状态实时可见；重连先补快照；切群不串流；终态收敛 | 快照、成员、任务状态与流处理需统一；依赖 F05/F07 |
| F09 | 动态成员与人类 @ 指派 | 自动入群且只播报一次；输入框补全已注册 Agent；未知目标报错；显式指派实际影响执行者 | 目前 @ 多为入群且 UI metadata 未发送；依赖 F06/F08 |
| F10 | 人工求助与准确答复 | 展示问题原文/来源/状态；答复指定干预并续跑同一远程任务；多个提问不误答；等待时输入可用 | 当前默认答复首个 pending；前端 input-required 误作新任务条件；依赖 F08 |
| F11 | Agent 间求助与动态协助节点 | LLM 决定 peer 或 human；助手为可见节点；完成后回填原远程任务；嵌套协助、复用、失败降级可验证 | 已有部分逻辑，需保持等待期间正确任务状态；依赖 F07/F10 |
| F12 | Agent @ 仲裁与防循环 | 自引用/未知目标忽略；同工作合并或复用；新增协助可见；mention/深度上限；拒绝有播报 | 当前派生总数限制不等价于深度限制；依赖 F09/F11 |
| F13 | 引用已完成消息并追问 | 引用块可跳转；准确定位 Agent/节点/任务；新节点或新任务携带原结果；不向远程终态 Task 追加 | UI 引用未接通；跨任务引用需统一 ID；依赖 F04/F08 |
| F14 | 运行中插话与排队补投 | 无关消息独立处理；引用在途工作排队；continue/完成/失败/取消后投递规则明确；角标准确且不重复投递 | 当前默认第一在途节点，多个终态路径未覆盖；依赖 F10/F13 |
| F15 | 指定工作打断与任务取消 | 明确目标、二次确认；远端取消；被取消分支不继续产出；新要求转接；其他并行工作不被误取消 | 当前打断默认 active[0]；依赖 F14 |
| F16 | 超时、自动重试与失败重规划 | 超时/错误可见；次数与退避正确；重试耗尽后按配置失败或重规划；计划版本保留，旧事件不污染新计划 | 当前重规划直接替换节点，历史/产物 ID 隔离需验证；依赖 F07/F08 |
| F17 | 共享上下文与摘要压缩 | 派发含指令、依赖、相关引用和群历史；预算裁剪；摘要可追踪；摘要失败不阻塞；不可信内容围栏 | 当前主要为跨任务文本 brief；依赖 F04/F07/F13 |
| F18 | 重启恢复与远端对账 | 执行中/等人/协助中/排队中重启可恢复；已知远端不重复派发；不可恢复明确失败；普通启动不清库 | 当前模拟启动有清库/端口过期问题；发出未记录 ID 的对账需设计；依赖 F10–F17 |
| F19 | ChoirWorks 群嵌套 | 外层注册内层；发送/产物/等待/答复/取消贯通；内层非阻塞返回后外层继续跟踪 | 已有单一路径测试，需扩展多轮控制；依赖 F03/F10/F15/F18 |
| F20 | 最终运行交付 | 实际启动命令、环境配置、模型 Key 指引、前后端地址与文档一致；全场景验收表；构建/测试通过 | 生产托管方式待选择；依赖此前各项用户验收 |

F01 仅交付确定性模拟规划及可核验样例，不把会话/UI/恢复等未完成能力包含在“演示已完成”之中。

## 5. 明确非目标

分布式、多租户、用户系统、多人类协作、外部副作用补偿、Agent 自治监听/P2P、私聊、附件/语音、消息编辑删除、会话删除归档、DAG 编辑器、移动端专项优化。若用户扩展范围，再加入独立功能点。

## 6. 逐项交付规则

1. 每次只实现当前一个功能点及其必要依赖，先明确验收脚本。
2. 功能提交验收时提供：变更说明、自动化验证结果、可操作的手动步骤、限制和关联文件。
3. 状态依次为：未开始 → 开发中 → 待用户验收 → 用户确认。测试通过不能替代用户确认。
4. 用户提出修改时只修当前项；用户确认后再开始下一项。不自动合并主分支或发布。
5. 范围尚未确认的历史功能保持待定；不会直接删除，也不会用过时接口实现冒充新版能力。

### 用户验收

新版后端已运行在 8567，独立数据库 `data/rebuild-f01-20260920.db`；旧的模拟数据库保留。打开 http://127.0.0.1:5173/，按以下步骤操作。每个样例点“新对话”，展开原始事件查看 metadata 中的计划/节点。

1. 发送“帮我分析上季度的财务数据并生成报告”：计划只有 finance-analyst，能看到产物及任务完成。
2. 新对话发送“帮我调研技术方案并写一份设计文档”：product-manager → developer，不应出现 auditor 或财务分工；传给节点的 input_text 不包含 Available agents/For context。
3. 新对话发送“请审批这笔采购申请”：approval-manager → finance-analyst；当前进程第一次审批会失败一次，然后第二次成功。
4. 其余 4 场景可按 README 示例执行。代码评审会停在人工提问；前端答复路由归 F10，完整协议答复已通过自动化验证。

本功能不意味着群聊页面、持久会话、跨任务引用或重启恢复已完成。模拟 Agent 的首次失败/首次求助以进程计数，需要复现时可运行各自隔离的 `uv run pytest tests/integration/test_sim_scenarios.py -q`。
